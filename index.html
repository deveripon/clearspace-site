Safety

Built around one rule: never delete what you need

Every path is checked twice: once when it is found, and again right before it is touched. When Clearspace can’t be sure, it doesn’t offer the item.

  • A review step before every clean, with Cancel focused
  • Duplicates and downloads go to the Trash, not deleted
  • Your branches and commits always stay in your repo

Locked, never offered

An agent worktree is locked when it has

  • Uncommitted or untracked changes
  • A .env or other ignored file that isn’t in your main project
  • A git repository inside it
  • Commits on a detached HEAD
  • A git worktree lock

Commits that only a worktree’s own history knows about are saved under refs/clearspace-backup before it is removed.

How it works

Scan, review, clean

About a minute from opening the app to getting your space back.

  1. Step 01

    Scan

    Clearspace looks through your project folders and caches. Nothing is changed while it scans.

  2. Step 02

    Review

    Safe items you aren’t using are already ticked. Open any row to see what it is and what cleaning it means.

  3. Step 03

    Clean

    Confirm the list. Clearspace measures your disk before and after, so you see the space you really got back.

Install

Free and open source.
One command to install.

The script builds Clearspace on your Mac, signs it locally, puts it in your Applications folder and opens it. It takes a few minutes the first time.

  • macOS 12 or later, Apple silicon or Intel
  • Node.js 18 or later, and git
  • MIT licensed, no account, no tracking
Terminal
Install
$git clone https://github.com/deveripon/clearSpace.git && cd clearSpace && bash install.sh
Update
$cd clearSpace && git pull && bash install.sh
Uninstall
$rm -rf /Applications/Clearspace.app ~/Library/Application\ Support/Clearspace

FAQs

Questions? Answers.

If something isn’t covered here, open an issue on GitHub.

Ask on GitHub

Build caches, node_modules and download caches are generated files: your tools recreate them when needed. Anything Clearspace isn’t sure about is marked Check first or Locked and is never selected for you. Every item explains what happens after cleaning before you confirm.

Folders that git tracks are never offered. Worktrees with uncommitted changes, unique ignored files such as .env, nested repositories or detached commits are locked. Worktrees are removed with git worktree remove, never with --force, so branches stay in your repository.

pnpm shares package files between projects through its store, so the real data lives there. When you clean pnpm node_modules, Clearspace offers “Unused packages in the pnpm store”, which runs pnpm store prune. That is where the space comes back.

No. There is no account, no analytics and no network access. The scan, the checks and the cleaning all run on your Mac.

Clearspace isn’t notarized by Apple. Building it on your own Mac with the install script signs it locally, so macOS opens it normally. You can also read every line of code before you run it.

The project folders you choose in Settings, plus well-known cache locations such as ~/.npm and ~/Library/Caches. Your home folder itself, Library, hidden tool folders and app bundles are refused as project folders.
